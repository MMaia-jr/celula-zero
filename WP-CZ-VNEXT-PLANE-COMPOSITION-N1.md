## Episode design

The authorized execution, if later granted, should build and observe this whole
episode rather than isolated capability demos:

1. Marcos enters through the chosen CZ path and the same institutional Person
   and legitimate Célula Zero relationship are recognized.
2. He sees the current Dream and relevant durable context without supplying IDs
   or reconstructing technical history.
3. Essenthius, as a coherent institutional intelligence and not a model or
   executor, reads relevant Cell/work/state through bounded capabilities.
4. A real task is visible and actionable in Plane, mapped to—not equated with—
   the CZ Cell.
5. A development capability is discovered only when useful. Before execution,
   Marcos sees the proposed action, scope and consequence and explicitly
   authorizes it.
6. Codex app-server executes only the authorized development action. Result,
   tests and exact GitHub commit/PR references return to the institutional
   context with executor/source attribution.
7. CZ records the consequence and learning in its own semantics and exposes a
   readable projection from the operational surface.
8. Marcos exits and later returns; relevant identity, work, authorization,
   result and consequence continue without manual reconstruction.

## Gate A — Plane habitability

Can Marcos use Plane as the operational projection of the Célula Zero Cell
without understanding the integration internals or feeling that he left CZ to
operate a separate product?

Pass requires ordinary entry, recognizable Cell context, useful work, an
understandable return path, and preserved source/authority distinctions.

If Plane fails because of an observed human experience property:

`STOP → HUMAN REVIEW → HULY RE-ENTERS`

Do not build “Plane corrected by CZ.” Huly may re-enter as an alternative
candidate, subject to evidence and Human Direction.

## Gate B — Essenthius composition

Can the conversation reconstruct relevant context, discover a capability when
needed, and read or act on Plane work through documented, bounded interfaces
without hardcoding custom handling separately for every future capability?

Pass requires replaceable models/executors, attributable tool results, explicit
authority checks and a human-readable consequence. A successful model response
alone is not a pass.

## Gate C — CZ inside CZ

Can a real CZ development task reach Codex app-server under explicit human
authority, return the result and tests, preserve GitHub provenance, record a CZ
consequence, and continue after Marcos exits and returns?

Pass requires exact links/revisions for code and tests, a distinct executor
record, human authorization before execution, and attributable CZ consequence
and learning. Codex access does not grant general CZ authority.
