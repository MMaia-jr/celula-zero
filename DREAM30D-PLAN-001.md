# PLAN 30D v0.1 — CÉLULA ZERO

Cycle: `25262d4d-4014-474e-9e71-e485a06f09ba`
Phase at adoption: `PLANNING / OPEN`
Human Direction: Collective Dream v0.1
Authority before adoption: `AI SYNTHESIS / PLAN CANDIDATE`

## Planning principle

Optimize for evidence of capability, reduced founder plumbing and real external
benefit — not maximum software surface.

Preserve:
- `AI planning voice ≠ Human Plan`;
- `Plan ≠ execution`;
- `working primitives + poor composition ergonomics ≠ habitable system`;
- `internal N=1 ≠ external utility ≠ adoption ≠ PMF ≠ scale`;
- `cost attribution ≠ payment system ≠ API-credit resale`;
- `24/7 availability ≠ sovereign autonomous AI`.

For every proposed technology:
`ADOPT / MAP / EXTEND / MISSING`.
For every `EXTEND / MISSING`, state the concrete property lost without it.

## Gate 1 — Canonical continuity / self-understanding — target days 1–3

Goal:
a fresh agent can reconstruct what Célula Zero is, current Human Direction,
architecture, demonstrated capabilities, active constraints, uncertainties and
next safe gate without Marcos rebuilding the history manually.

First use existing Git, Room, handoff and bounded context mechanisms.
Do not build a new memory engine by default.

Test:
give a fresh agent only context generated/retrieved through Célula Zero and score
correctness, authority/temporal distinctions, unsupported invention, context load
and ability to return to original sources.

Promotion criterion:
correct reconstruction with no material authority/temporal error and materially
less manual founder reconstruction than the current workflow.

Falsifier:
Marcos still has to narrate substantial project history or the agent invents
current state/primitives.

## Gate 2 — Founder-light continuity / Plus independence — target days 4–7

Run a 48h probe first. If it passes, extend to 7 consecutive days.

During the test ChatGPT Plus must not be the critical memory or coordination
substrate. Free GPT/Kimi/Gemini, paid APIs and other replaceable capabilities may
participate.

Marcos may perform necessary human relay for free web UIs, but should not need to
manually assemble history, reconcile state or design each technical handoff.

Promotion criterion:
work continues with reconstructible state across sessions/providers and Plus can
be removed without organizational amnesia.

Falsifier:
workflow halts or loses critical context when external chat history is absent.

## Gate 3 — Bounded self-improvement — target days 4–14

Agents repeatedly use:
`inspect → identify real friction → classify ADOPT/MAP/EXTEND/MISSING →
smallest change → test → verify → reflect`.

Execute up to three distinct improvement cycles only when each addresses a new
observed uncertainty.

A current candidate seam is new-AI onboarding: Gemini required explicit actor,
operator membership, participation and attribution plumbing. Do not assume a
generic onboarding platform; first identify the property actually lost.

Promotion criterion:
at least one real improvement reduces measured founder/technical plumbing while
preserving authority and provenance; further cycles require new uncertainty.

Falsifier:
agents merely propose more architecture or require Marcos to repair the
self-improvement process manually.

## Gate 4 — Resource metabolism — target days 8–17

Before payments or credit systems, make resource use legible:

`action → organization/project → AI actor → provider/model/access mode →
usage → cost → responsible budget/authority`.

Preserve free/manual UI handoffs as `FREE_UI / HUMAN_RELAY`, not fake API calls.

Human budget hypothesis for this 30-day Dream:
approximately `USD 19` maximum paid AI Gateway/API expenditure unless Marcos
explicitly changes it.

Test real consumption before deciding BYOK/BYOC, organization-funded quotas,
pass-through or any future resale.

Promotion criterion:
material paid calls are attributable to their cause/context and total paid spend
can be reconstructed.

Falsifier:
cost cannot be attributed or sustainable use requires an unplanned subsidy that
the current economic model cannot explain.

## Gate 5 — 24/7 thin slice — target days 11–18

Define 24/7 minimally:
while Marcos is offline, Célula Zero can receive an authorized input/event,
preserve it without corruption or loss, expose its provenance and make it
reconstructible for later continuation.

Model inference need not run continuously.

Test existing Git/Supabase/standard infrastructure before creating any daemon or
orchestrator.

Promotion criterion:
an offline-hours input survives, is attributable and can be safely resumed.

Falsifier:
input is lost, silently changes state, or requires an always-present founder to
remain meaningful.

## Gate 6 — Second human / external utility — target days 18–24

A real non-builder uses Célula Zero for a real problem.

The person should obtain an observable benefit without Marcos acting as live
translator or manually repairing the workflow.

Observe separately:
entry, action, relation, delivered result, real-world consequence and return.

Promotion criterion:
measurable benefit for a non-builder and a reconstructible account of what the
system — versus Marcos — contributed.

Falsifier:
the person cannot obtain a useful result or use depends primarily on founder
intervention.

## Gate 7 — Second organization — conditional stretch gate — target days 25–28

Attempt only if earlier evidence makes organization separation the next real
property.

Required properties to inspect:
identity, authority, memory/context, data, secrets, budget/cost, artifacts,
export/deletion and portability.

Prefer current relational/scoping primitives and existing infrastructure first.

If second-human habitability is still the binding constraint, spend this period
on another utility/improvement cycle instead of multi-tenancy.

## Gate 8 — Independent review + Celebration — target days 29–30

Freeze a reconstructible evidence package covering:
- self-understanding;
- founder/Plus dependence;
- improvements executed;
- resource/cost trajectory;
- 24/7 result;
- external utility;
- security/privacy/portability;
- second-organization result if attempted;
- failures and unresolved blockers.

Independent agents must be free to return:
`STARTUP WORTH PURSUING` or `NOT YET`.

`STARTUP WORTH PURSUING` means only:
there is enough evidence of useful, repeatable, increasingly founder-light and
economically plausible capability to justify pursuing a startup.

It does not mean:
validated startup, PMF, adoption or scale.

Marcos retains the Human Decision.

## Explicit non-critical-path items

Do not build by default:
- generic orchestrator;
- RAG/vector database;
- graph database;
- API-credit marketplace/resale;
- database-per-organization;
- custom frontend;
- token/DAO;
- continuous autonomous model runtime.

Any of these may return only after a concrete lost property is observed.
