## Construction discipline

Preparation does not mean building commodity infrastructure from zero or
anticipating every possible future requirement.

Continue:

`READBACK → ADOPT / MAP → COMPOSE → EXTEND → BUILD FROM ZERO only when necessary`

For `EXTEND` or `MISSING`, ask:

> What concrete property is lost if we do not create this?

Without concrete property loss, do not build.

The readiness program should prefer existing standards, maintained
open-source systems and mature external infrastructure when they preserve the
required property without surrendering legitimate Human authority, provenance,
privacy, portability or exit.

## Genesis readiness envelope

Before external transfer, Genesis should be able to exercise, in an integrated
way, the capabilities it chooses to offer across at least:

1. identity and presence;
2. Dream / Need / Intent from Human expression;
3. Cell / Space / Project context and local sovereignty;
4. Discovery / social surface;
5. deliberation, governance, delegation and revocation;
6. planning and work;
7. bounded Human–AI operation;
8. result, evidence, verification and Human Decision;
9. real economic consequence through existing rails when applicable;
10. treasury/accounting boundary;
11. memory and provenance;
12. privacy and contextual disclosure;
13. portability, exit and autonomy;
14. continuity, restart, recovery and provider/executor substitution.

This is a readiness envelope, not a requirement to create fourteen new
technical subsystems.

The transversal usability requirement is:

> A nontechnical Human should not need to understand the internal architecture
> in order to use the experience legitimately.

`AI CONSENSUS ≠ HUMAN LEGITIMACY`
