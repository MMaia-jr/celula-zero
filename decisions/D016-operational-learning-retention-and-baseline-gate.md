### Direction 1 — Operational Learning Retention

A material incident in Célula Zero is not considered closed merely because the
immediate error was corrected.

When an incident reveals a falsified assumption or changes how future work
should be executed, preserve the smallest durable learning appropriate to the
case:

`observed incident → falsified assumption → generalized rule → regression/preflight when applicable → durable retrievable record`

Preserve:

`FIXED ONCE ≠ LEARNED`

Prefer existing structures first:

- Result Package for the concrete episode and evidence;
- `PROTOCOL.md` for generalized reusable operating rules;
- deterministic test or preflight for machine-enforceable consequences;
- `STATE.md` only for short current consequences / active gates;
- Git history for lineage.

Do not build a new memory platform, RAG layer, graph, database or agent merely
to preserve this learning unless a concrete property is shown to be lost.

### Direction 2 — Habitable internal path followed by a simple baseline

The next strategic preparedness gate is:

`CLEAN HABITABLE INTERNAL N=1 → SIMPLE BASELINE N=1`

First demonstrate one real internal problem through a sufficiently clean Célula
Zero path without manual UUID, SQL, `psql` or bespoke recovery plumbing.

Then compare the same or closely comparable problem against the simplest
ordinary alternative, such as a normal AI interface plus files, GitHub,
messaging and ordinary delivery.

Measure consequential properties rather than internal record count, including
when applicable:

- wall-clock time;
- founder plumbing time;
- output usefulness / quality;
- reconstructibility after time has passed;
- beneficiary evaluation;
- preference for reuse.

No new infrastructure is justified by the comparison unless a concrete property
is lost in the simpler baseline.
