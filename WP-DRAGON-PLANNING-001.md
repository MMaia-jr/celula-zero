## Planning method to test

Planning is not “write tasks immediately”.

### P1 — Generative objective round

Starting question:

`What things need to happen to enable 100% of our Human-adopted Collective Dream to come true?`

Each role proposes bounded necessary conditions.

Expected output:

`candidate objective set`

Target range for review:

`approximately 6–8 objectives`

This is a working range, not an invariant.

### P2 — Goal / objective refinement

Agents may:

- restate;
- ask questions;
- challenge hidden assumptions;
- identify duplicates;
- distinguish objective from task;
- identify leverage/dependency;
- suggest simpler alternatives.

AI convergence, ranking or straw polling is advisory:

`AI convergence ≠ Human adoption`

Gate:

`HUMAN REVIEW / ADOPT OR CORRECT GOAL + OBJECTIVES`

No Karabirrdt construction before that gate.

### P3 — Alternatives / strategies / falsifiers

For each Human-adopted objective:

- simplest existing option;
- alternatives;
- hidden assumptions;
- concrete property at risk;
- cheap test;
- falsifier;
- `ADOPT / MAP / EXTEND / MISSING`.

Technology names are not objectives.

### P4 — Karabirrdt candidate

Only after Human adoption of Goal/Objectives.

Represent:

- tasks;
- dependencies / songlines;
- milestones;
- already-started or completed work;
- bottlenecks;
- tasks that unblock many others;
- internal-community orientation;
- external-community orientation.

Start with repository-native Markdown/JSON or another existing representation.

Do not build a graph database, new planning platform or custom visual system
unless a concrete property is lost.
