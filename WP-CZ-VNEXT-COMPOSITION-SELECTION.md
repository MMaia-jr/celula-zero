## Mission

Select the smallest mature, reversible composition that lets one human inhabit
Célula Zero as a coherent institution, with CZ retaining its distinctive
semantics and authority. This Work Packet records a future inquiry; its
execution is not authorized by D056's documentation-promotion authorization.

`MARCOS ENTERS CZ → INHABITS CÉLULA ZERO → DREAMS / PLANS / DOES / CELEBRATES → OPERATES / DEVELOPS / GOVERNS CZ → ESSENTHIUS ROUTES CAPABILITIES → CONSEQUENCES REMAIN DURABLE → RETURN CONTINUES`

The selection is about the lived composition, not a feature-count contest or a
decision to preserve the current implementation. Do not implement, migrate,
configure, purchase, deploy, connect accounts, or alter PR #229 as part of the
selection unless a later Human Direction explicitly authorizes that work.

## Required decision question

For each ordinary human episode, can Marcos enter by a persistent, ordinary
path; understand why he is here and what continues; use the Cell to dream, plan,
do and celebrate real work; see consequential proposals and actions under human
authority; and return later without manually reconstructing technical context?

Do not count a page, feature, API, table, integration, test, deployment or
available model as preserving an experience unless the composition makes that
property usable in the human path.

## Candidate scope

The future selection must investigate, using current primary documentation and
bounded product use where access already exists:

1. **Principal collaborative workspace:** Huly versus Plane, without a
   preselected winner. Determine whether either can be the ordinary place for
   Célula Zero work and whether CZ semantics can compose cleanly around it.
2. **Social, Profile and community surface:** first test whether the selected
   workspace and CZ's current identity/profile capability suffice. If not,
   compare HumHub or a materially better alternative. Do not add a community
   product just to reproduce social features.
3. **Conversation and action UI:** assistant-ui + AI SDK as the current
   composition candidate. Verify how thread state, tool/action approval,
   identity, data ownership and navigation join the human flow.
4. **Development and execution:** Codex + GitHub as existing capabilities for
   CZ development and canonical state. Determine how work enters/returns to the
   Cell, and keep executor access distinct from institutional authority.
5. **Institutional substrate:** CZ semantics/packages with existing Supabase,
   GitHub and relevant current CZ records. Select only the smallest owned
   semantics needed to retain identity, authority, provenance, continuity and
   durable consequences.

Use the PR #229 implementation as a preserved integrated candidate and
selective technical substrate, not as the default product composition. The
selection must say what can stop being built or maintained if mature surfaces
are adopted.

## Evidence and comparison rules

For every factual capability, cite the current primary source, date checked and
the exact user-facing flow or administrative condition. Separate:

`DOCUMENTED ≠ AVAILABLE IN OUR PLAN ≠ CONFIGURED ≠ INTEGRATED ≠ HABITABLE`

Where a short real-use observation is required, record the entry, human action,
visible consequence, return path and unresolved barrier. Do not create accounts,
connect private data, configure production, pay for plans or run an integration
without explicit authorization. A product walkthrough or demo is not adoption.

Do not use an aggregate feature score. Explain direct trade-offs in these terms:
human habitability, context/identity continuity, authority and provenance,
integration surface, operating and security burden, exit/reversibility, and
which custom work CZ can stop.

## Required decision tests for each composition

Answer for each candidate and the leading composition:

- What must we believe for this to be the right path?
- Which observed evidence would falsify it?
- What would we regret building or binding ourselves to?
- What could be deleted, archived or left as lineage?
- What can be adopted immediately without changing CZ data or authority?
- What exact human property is lost if we omit it?
- What is the smallest irreversible decision, and can it be deferred?

## Deliverable and stop conditions

The result must recommend one smallest composition, state remaining uncertainty,
map capabilities to ADOPT / MAP / COMPOSE / EXTEND / MISSING, list the code and
infrastructure CZ can stop building, and define one coherent human episode that
would validate the composition later. Include source links and separate FACT,
OBSERVED, INFERENCE, RECOMMENDATION and HUMAN DECISION REQUIRED.

Stop without a selection if current authoritative evidence is unavailable, an
essential authority/provenance/exit property cannot be evaluated, or a choice
would create high-cost lock-in requiring Human Direction. In all outcomes:

`D056 CANONICAL ≠ COMPOSITION SELECTED`

`COMPOSITION SELECTED ≠ INTEGRATED`

`INTEGRATED ≠ HUMAN CAN USE IT`

Execution, account connection, migration, implementation, deployment or product
promotion requires separate explicit Human authorization.
