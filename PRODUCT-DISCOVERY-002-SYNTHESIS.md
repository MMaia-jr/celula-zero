## What is relatively supported

1. `Profile` is more plausibly a projection of an Actor and their relations,
   history and current context than a large form that is the product itself.
2. Existing external trust mechanisms should be reused when they preserve the
   required property. Examples include provider authentication, proof of account
   control, LinkedIn verification signals, GitHub activity/signatures, ORCID and
   domain control.
3. External authentication, identity verification and contextual trust are
   distinct.
4. Shared historical objects with multiple participants and roles already have
   strong precedents. Co-participation is therefore not established as `MISSING`.
5. Historical bootstrap can use self-claims, artifacts, external sources and
   attributed third-party claims without pretending that the platform observed
   the past.
6. Native history can be epistemically richer because the system can preserve
   intention, relation, commitment, action, contribution and result as they
   occur; richer provenance still does not make an event automatically true,
   useful or positively assessed.
7. Demand and activity cold starts are harder product problems than simply
   creating identity/profile data.
8. A social product cannot rely on a semantically better profile alone. Negative
   precedents such as Polywork and Google+ reinforce that representation,
   distribution and conceptual differentiation do not establish recurring use.
9. WhatsApp is an existing coordination channel worth adopting initially when
   it preserves the needed property. Native messaging is not justified merely
   because the future product may be social.
10. No new requirement for blockchain, token, DAO, universal score, graph DB,
    AI-first interface, native payments or sophisticated matching was
    demonstrated by this discovery cycle.

## Strongest integrated working model so far

The strongest synthesis is not three separate products but complementary
functions around one possible cycle:

```text
SHARED HISTORY
  -> bootstrap of past/context/relations

PROJECTS / NEEDS / OPPORTUNITIES
  -> present utility and coordination toward action

LIVE WORLD
  -> discovery surface over real things happening

PROFILE
  -> projection of Actor + relations + history + current context
```

Potential shared cycle:

```text
Intention
-> Discovery
-> Relation
-> Project / Context
-> Need / Opportunity
-> Commitment
-> Action
-> Contribution
-> Result
-> History
-> Contextual Capacity / Trust
-> New Opportunity
```

This is a `WORKING HYPOTHESIS`, not a product definition proven by users.

## Reconstructed history != native history

### Reconstructed history

```text
self-claim
+ artifact
+ external source
+ attributed third-party claim
+ external verification signal when applicable
```

The platform did not observe the original occurrence.

### Native history

```text
intention
-> relation
-> proposal/interest
-> commitment
-> action
-> contribution
-> artifact/result
-> claim/evidence
-> verification/assessment when explicitly performed
```

Preserve:

`COMMITTED != EXECUTED != VERIFIED`.

## Multiple-entry-point hypothesis

There may be no universal first action.

Different people may enter through different needs:

- `I want to do/learn something`;
- `I need someone`;
- `I can offer something`;
- `something I did before matters now`;
- `someone I worked with brought me into this context`.

The important question is whether these entries converge into the same useful
cycle rather than forcing every user through the same profile/onboarding task.

## What remains open

- Which entry point produces voluntary action for which person/context?
- Does Projects/Needs/Opportunities generate utility beyond existing referral +
  WhatsApp flows?
- Does shared-history bootstrap provide benefit to the invited participant, or
  mostly a favor to the inviter?
- Can a Live World remain relevant without artificial supply or a large network?
- Does contextual history actually change a later real decision?
- Does native history reduce the representation burden for people with real
  capacity but weak digital self-presentation?
- Can a learner enter through intention, participate in real work and leave with
  legitimate first evidence/capability rather than a fabricated credential?

## Product-discovery stop condition

small real-user test.

Next evidence should come from observed use rather than another broad survey of
platforms unless a new uncertainty specifically requires research.
