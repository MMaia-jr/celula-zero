# HABITABLE-ALPHA-001 — EXTERNAL ACTION / HISTORY SLICE

State: `PREPARED / NOT EXECUTED`
Class: `PRODUCT EXPERIMENT`
Date: 2026-08-23

## Purpose

Move the Célula Zero product inquiry from broad research to observed external
utility using the smallest real-world vertical slice that can test the
integrated action/history cycle with one external participant.

HABITABLE-ALPHA-001 is not designed to select the universally "best" entry
mechanism. It records which legitimate entry the participant naturally uses
first and whether the integrated cycle produces utility.

This is not a launch, PMF test, scale test or complete social-network MVP.

## Central question

Can one real person who was not involved in building Célula Zero:

1. encounter a small real context without needing to understand the protocol;
2. find or express a reason to act;
3. establish a relation with another real person;
4. produce a real-world consequence;
5. leave behind an honest contextual history of what actually occurred; and
6. have a concrete reason to return when something relevant changes?

## Scope

Use:

- 1 real external participant;
- 1 small real context;
- 1 real need/project/activity;
- 1 real capacity or learning intention;
- 1 real second person;
- optionally 1 real past shared occurrence if historical bootstrap is useful.

No synthetic participant or fake opportunity may be presented as real.

## Entry mechanisms available when legitimate

The three mechanisms are candidate entry surfaces into one integrated cycle, not
three products and not a causal A/B/C comparison in `N=1`.

### A — Discover / Act

User can see a real thing they could participate in or help with.

### B — Need / Create

User can express a real need, project or opportunity that requires another
person.

### C — History / Context

User can record or respond to a real past occurrence involving another person.

If no legitimate shared past occurrence exists in the selected context,
mechanism C is `NOT TESTED`. Do not manufacture one merely to complete the
experiment.

The interface labels may differ. The experiment observes behavior and natural
entry, not wording preference or a causal comparison among the three mechanisms.

## Controlled variables

To keep observations comparable and avoid giving one entry mechanism an
artificial advantage, preserve where applicable:

- same people;
- same real context;
- same underlying information/evidence;
- same communication channel (prefer existing channel such as WhatsApp unless a
  concrete property requires native chat);
- no financial referral incentive;
- no fabricated supply;
- no hidden AI-generated decision.

## Observed chain

Primary observation chain:

```text
ENTRY
-> ACTION
-> RELATION
-> SECOND PERSON
-> REAL-WORLD CONSEQUENCE
-> RETURN
```

Each transition must be recorded separately. Do not infer later transitions
from earlier ones.

Examples:

- clicking `interested` != participating;
- accepting a role != executing it;
- executing != producing the intended result;
- artifact exists != claimed role verified;
- returning after a reminder != spontaneous recurring utility.

### Operational meaning of real-world consequence

At least one materially external consequence must occur. Candidate examples:

- real participation actually occurs;
- a real introduction is accepted and changes who can act with whom;
- a real commitment is established;
- a contribution or artifact is actually produced;
- a real decision changes because of the interaction/context.

The following do not count by themselves:

- view;
- click;
- signup;
- like;
- declaration of interest;
- message sent.

## Minimum result package

Record:

### Original Records

- participant's own words at key points when consented/appropriate;
- original request/need or historical claim;
- relevant real artifacts/links only when lawful, necessary and consented.

### Observations

- what entry mechanism was used;
- what action occurred;
- whether another person became involved;
- what actually happened outside the interface;
- what information/context the system preserved;
- whether/why the participant returned.

### Interpretation

Keep researcher interpretation separate from participant records and observed
behavior.

### Classification

One of:

`PASS / FAIL / PARTIAL / INCONCLUSIVE`.

## PASS N=1 candidate criterion

A candidate `PASS N=1` requires all of the following to be observed, not merely
intended:

1. external participant understands at least one available action without a
   private explanation of Célula Zero philosophy;
2. participant voluntarily takes a real action;
3. action establishes or materially changes a relation with a second person;
4. a real-world consequence occurs;
5. Célula Zero can preserve what happened without collapsing commitment,
   execution, result, evidence and verification;
6. a later change creates a concrete reason for the external participant to
   return or re-engage.

If item 6 is not observed, classify at most `PARTIAL` for the full habitability
claim even if a useful one-shot action occurred.

## Important secondary questions

- Which legitimate entry mechanism was naturally chosen first? (This observation does not establish a universal winner.)
- Did Shared History provide value to the invited person or only to the inviter?
- Did Projects/Needs/Opportunities add anything beyond existing referral +
  WhatsApp?
- Did a profile emerge naturally from activity/history?
- Did contextual history alter any later real decision?
- What property, if any, was lost by using an existing communication channel?
- What product capability was actually missing during the run?

## Privacy / LGPD precondition

Before involving an external participant, define the exact personal data needed
for this run and minimize it.

Default:

- do not ingest contact lists;
- do not store identity documents;
- do not copy external profiles when a reference/signal is sufficient;
- do not expose another person's participation publicly without a defined lawful
  basis/consent appropriate to the scenario;
- keep repository fixtures free of real participant personal data.

If the test can be executed with manual links and pseudonymous/local notes, do
not build a personal-data pipeline merely for convenience.

## ADOPT / MAP / EXTEND discipline

Before implementing any missing capability ask:

> Can the property be preserved with an existing standard, process or current
> canonical object?

Classify:

- `ADOPT` existing mechanism is sufficient;
- `MAP` current model can represent it;
- `EXTEND` small concrete property is otherwise lost;
- `MISSING` only after reasonable negative evidence.

No implementation is justified solely because the UX uses the words
`Experience`, `Attestation`, `Feed`, `Community` or `Profile`.

## Explicit non-goals

Not part of HABITABLE-ALPHA-001 unless a run demonstrates a blocking property:

- universal reputation;
- scoring/ranking;
- full marketplace;
- payment custody;
- financing flow;
- smart-contract demonstration;
- blockchain/token/NFT/DAO;
- graph database;
- native real-time messaging;
- recommendation engine;
- AI-first interface;
- mobile-native app;
- full community system;
- scale/performance architecture.
